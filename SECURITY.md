# Security

Use trusted MCP clients and an appropriately scoped ESXi account. The server can mutate or delete VMs, host configuration, networking and storage. TLS verification is enabled by default; writes, advanced writes and optional SSH administration are disabled by default. All mutation tools preview by default.

The read_only/operator/administrator deployment profiles, exact targets, allow/deny patterns and call acknowledgements constrain execution. ESXi itself enforces account privileges. A dry-run validates typed input and local guards; it does not simulate server execution or prove safety/support. Host API operations can cut the same connection needed to inspect or recover them.

Direct protected VM/snapshot writes are blocked in ordinary tools. The generic API permits explicit administrator control only with both deployment and call protected-impact opt-ins. Shared network/datastore/file operations conservatively identify affected VMs and require their IDs; management disruption has an additional deployment/call opt-in. Protected datastore/network names are denied outright. File uploads protect known management VMX and external backing-file directories. Unknown managers/shell are treated as host-wide. This is not complete dependency inference for every device, vendor extension or opaque API argument; use ESXi roles as the privilege boundary and recheck VM IDs after re-registration.

Keep credentials, private SSH keys, signed URLs, raw evidence, audit files, SQLite state and staged bytes outside the repository. Directory/file permissions are restricted on Unix; configure Windows ACLs. Structured secrets, known API passwords, license keys, signed URL fields and base64 payloads are redacted. Opaque shell/ESXCLI arguments are represented by digests in logs/journals; SSH output is omitted from durable records. Arbitrary API strings may still contain unrecognized secrets. Returned data can contain private infrastructure and temporary file URLs required for authorized calls.

HTTP cookie-bearing requests are restricted to the configured ESXi HTTPS authority and datastore/recognized guestFile/NFC endpoints; redirects are refused. External source uploads require trusted HTTPS URLs. Inline transfers are limited to 8MiB; background transfers are bounded to an explicit maximum with disk reserve checks. Uploads cannot guarantee remote byte-level resume. Do not treat a cancelled/timed-out upload as absent remotely. NFC heartbeat and original authenticated session remain in one MCP process, with a configurable 86400s retention bound; a process restart interrupts leases/workflows.

The optional SSH backend requires a verified SHA256 host-key pin or trusted known_hosts file and rejects unknown/unmatched identities. It is a separate ESXi administration credential, not the MCP transport key. Fixed query commands are selected by the server; arbitrary argv/shell writes require administrator and whole-host impact opt-ins. Commands are not automatically retried. Use a dedicated forced-command key with forwarding disabled for remote MCP transport. This release exposes stdio only.

Durable records do not guarantee exactly-once distributed execution: a connection can fail after ESXi accepted a request. Inspect task/resource state before a new request. Plans only execute supplied compensations for completed steps and skip automatic compensation after an uncertain failure. Compensation is not atomic recovery. Staged files remain until an operator removes them; inspect active jobs first.

Use disposable acceptance resources. Do not disclose credentials/exploitable details in public issues. Use private GitHub vulnerability reporting when enabled, otherwise request a private maintainer channel; no reporting endpoint is configured in this bundle.
